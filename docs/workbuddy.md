# WorkBuddy 本地验收

这是人工协作的验收流程，不代表 WorkBuddy 已成功安装或调用本技能。不要把检查器直接执行成功称为宿主集成测试通过。

## 结构依据

参考 [WorkBuddy 官方技能文档](https://open.workbuddy.cn/docs/skill)（2026-10-29 查阅）。当前入口除通用 name/description 外，补充了官方文档列出的展示名、中英文介绍、版本和作者字段。文档的市场上架字段要求不等于所有本地版本的导入要求；本地导入行为仍须实际验证。无需为了本地测试发布到市场。

测试包应仅包含：

```text
skill-lens/
  SKILL.md
  LICENSE
  scripts/
    check.mjs
```

不要将故障样例安装为技能，不要将整个仓库作为一个技能上传。检查器需要 WorkBuddy 的执行环境能够使用 Node.js 22+。

## 安装

在 WorkBuddy 的技能管理入口使用其本地导入功能（若当前版本提供），选择本地测试 ZIP。菜单和导入方式以实际版本为准。若找不到入口，可让 WorkBuddy 根据本机版本的机制，从本仓库的 `skills/skill-lens/` 安装技能；保留入口与脚本的相对结构。

仅授权安装本技能，不覆盖同名已有技能，不修改其他技能，不自动下载运行时或设置全局配置。存在同名技能时先核对来源。安装完成后，新开对话或按宿主要求刷新，确认列表中可发现 `skill-lens`。遇到导入错误，记录原始错误或截图，不要凭空推断宿主不兼容。

## 故障样例调用

将下方占位符替换为本仓库的真实绝对路径后发给 WorkBuddy：

```text
使用已安装的 skill-lens，扫描我明确授权的目录 <仓库绝对路径>/examples/broken。
只执行此技能自带的检查脚本，不运行扫描目标内的命令，不修改文件，不上传文件。
先给简明结论，再按优先级说明各条发现的位置、影响和建议，不要使用需要横向滚动的大表格。
将真实执行命令、退出码与原始规则编号放在最后的技术详情，保留可核对的证据。
区分确定问题、潜在风险和未知；不要把重名说成已证实的覆盖或语义冲突。
如果未找到技能或缺少 Node.js，请如实说明，不要另写检查器代替。
```

预期：退出码 1，发现 NAME_COLLISION、REFERENCE_MISSING 和 METADATA_MISSING。缺失引用指向 `alpha/SKILL.md:7`。其他发现可能没有行号，不应编造行号。应给出 1 条 error 和 2 条 warning。

随后在另一条请求中明确授权 `examples/healthy`：预期退出码 0，无发现。扫描干净不等于安全认证。

## 验收依据

保留该次对话中的技能加载记录（若宿主提供）、实际工具调用及其输出。确认实际运行的是安装目录中自带的脚本，而非扫描目标中的脚本。仅最终自然语言回答不能证明脚本确实运行。

检查模型是否引用真实证据、未扩展到用户目录、未自动修复、未夸大结论。执行前后可比较样例文件哈希，确认目标内容未变；这不能证明执行期间完全没有任何其他副作用。

实际调用记录、宿主版本、执行环境、发现数量及文件未变证据尚未收集前，宿主验收状态应保持“待验证”。分享结果前隐藏账号、凭据及无关私人路径。
